# NeuraHive Architecture Decision Records

Architecture Decision Records (ADRs) capture decisions that constrain the v2 implementation. New architectural decisions should be recorded here rather than buried in implementation commits.

## Index

- [ADR-0001 — Core / Platform Boundary](0001-neurahive-core-platform-boundary.md)

## ADR rules

1. One architectural decision per ADR.
2. State context, decision, consequences, and rejected alternatives.
3. Mark the status explicitly: Proposed, Accepted, Superseded, or Rejected.
4. Update the master roadmap when an ADR changes a phase boundary or dependency.
5. Do not use ADRs to document routine implementation details.
